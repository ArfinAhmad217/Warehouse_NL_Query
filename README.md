# 🏭 Warehouse Natural Language Query Assistant

An AI-powered **Natural Language to SQL** assistant for warehouse capacity and inventory analytics.

Users can ask warehouse-related questions in natural language, and the system uses **RAG + LLM + Text-to-SQL** to understand the question, generate a safe SQL query, execute it against the warehouse database, and return a clear natural-language answer.

---

## 🚀 Features

* 🤖 Natural Language → SQL generation
* 🔎 RAG-based database schema retrieval
* 🧠 Sentence Transformer embeddings
* 🗄️ ChromaDB vector database
* 🔐 Read-only SQL safety validation
* 📊 Warehouse capacity & inventory analytics
* 💬 Natural-language answers generated by LLM
* ⚡ FastAPI REST API
* 🗃️ SQLite database with automatic sample data seeding
* 📚 Swagger/OpenAPI documentation

## 🧠 How It Works

### 1. User asks a question

Example:

> "Kaunse chamber me is month sabse zyada capacity used hui?"

### 2. RAG retrieves relevant context

The system searches the ChromaDB vector store for relevant warehouse schema and domain knowledge.

The retrieved context can include:

* `chambers`
* `capacity_logs`
* `inventory_snapshots`
* `products`
* Capacity calculation rules
* Example SQL patterns

### 3. LLM generates SQL

The LLM receives the user question together with the retrieved schema context and generates a SQLite-compatible SQL query.

### 4. SQL safety validation

Before execution, the generated query is validated.

Only read-only `SELECT` queries are allowed.

Potentially destructive operations such as:

* INSERT
* UPDATE
* DELETE
* DROP
* ALTER
* TRUNCATE

are rejected.

### 5. Database execution

The validated SQL query is executed against the warehouse SQLite database.

### 6. Natural-language response

The query result is sent back to the LLM, which converts the raw database result into a concise human-readable answer.

## 🗄️ Database Schema

### Chambers

Stores warehouse chamber information.

* `id`
* `name`
* `location`
* `total_capacity_cbm`
* `is_active`

### Products

Stores warehouse product information.

* `id`
* `sku`
* `name`
* `category`
* `volume_cbm`

### Inventory Snapshots

Stores point-in-time inventory information.

* `chamber_id`
* `product_id`
* `quantity`
* `snapshot_date`
* `used_capacity_cbm`

### Capacity Logs

Stores daily warehouse capacity utilization.

* `chamber_id`
* `log_date`
* `used_capacity_cbm`
* `total_capacity_cbm`
* `utilization_pct`

## 🔐 SQL Safety

Because the SQL is generated by an LLM, the application includes a safety layer before executing the query.

The system:

1. Requires the query to start with `SELECT`
2. Rejects destructive SQL operations
3. Executes only validated read-only queries

This prevents the AI-generated query from modifying or deleting warehouse data.

## 🔎 RAG Implementation

The project uses **Retrieval-Augmented Generation (RAG)** to provide the LLM with relevant warehouse-specific context before generating SQL.

The RAG pipeline consists of:

```text
Warehouse Schema & Domain Knowledge
            ↓
Sentence Transformer
            ↓
Vector Embeddings
            ↓
ChromaDB
            ↓
Similarity Search
            ↓
Relevant Context
            ↓
LLM
```

Embedding model:

```text
all-MiniLM-L6-v2
```
